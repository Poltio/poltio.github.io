A/B Testing

This page tests dynamic-content A/B tests. The snippet is the same as any other page — the server swaps in the union poltio_ab.js bundle under case variants, and the parent's own bundle under off, so nothing on this page opts in.

Expected behavior

  • The assignment is written to poltio_ab_<parent id> in localStorage as the chosen arm's widget id, or off for the holdout.
  • Storage outranks the server's assignment, so a visitor stays on the same arm across pages, utm_ params and reloads. The browser only rolls for itself when the rotation could not answer. Use Reset to re-roll.
  • Case variants: the chosen arm's options are applied to .poltio-widget-flying as data-poltio-* attributes, plus data-poltio-ab-widget-id. Arms can differ in trigger type, so the pill/card/box can change too.
  • Case off: decided by the same rotation as variants and baked into the bundle — held out or shown, not a percentage to roll against. Only the localStorage key shows it; there is no data-poltio-ab-widget-id on this path.
  • No widget plus = off is the holdout working, not a failure: that share renders nothing and reports no impression. Page-load and purchase tracking still fire.
